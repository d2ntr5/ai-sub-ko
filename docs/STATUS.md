## 상시 승인 · 규칙
- 사용자가 「릴리즈 해」라고 하면: 테스트 → 버전 올림 → 브랜치 · PR · 머지 → `make publish VERSION=x.y.z` → Release 확인 → 묶은 zip 을 작업 맥의 백업 공유(`apps/ai-sub-ko/dist/`)에 복사 · `cmp` 확인 → 보고. 스토어 제출은 하지 않는다.
- 시험은 늘 **시험용 크롬 프로필**(`--user-data-dir`)로. 사용자 크롬 프로필 · 사용자 설치본은 건드리지 않는다. 끝나면 크롬을 끄고 시험 프로필을 지운다.
- 시험 판정은 dev-guides `app-standards/ui-testing.md`: 시험 전에 「기대」를 적고 실제와 비교. 오류만 안 본 것은 「안정성만 봄」으로 따로.
- 윈도우 시험은 총괄이 연결해 준 원격 윈도우 세션에 맡긴다: 관리자 권한 · 설치 · 재부팅 금지, 시험 프로필만, 그쪽은 커밋하지 않음.

## 시험 도구 (저장소 밖)
- 실제 크롬 자동 시험은 CDP 로 한다 (`CLAUDE.md` 「실제 크롬 시험」): `--remote-debugging-pipe --enable-unsafe-extension-debugging`, `Extensions.loadUnpacked` · `Extensions.triggerAction`, 가짜 Claude · Gemini 응답 서버(ok · 429 · 529 · 401 · credit · prose).
- 지난 세션의 도구 스크립트는 세션 임시 폴더에 있어 사라졌다. 필요하면 다시 만든다. 음성 번역 시험 영상(macOS `say` 로 만든 영어 5문장 · 일본어 4문장 · 앞 25초 신호음 뒤 영어, 정답 글 포함)은 백업 공유 `apps/ai-sub-ko/windows/asr-test-20261117/` 에 있다.
- 로컬 시험 페이지는 `lecture.localhost:<포트>` 로 열면 강의 사이트처럼 동작한다 (영상은 Range 요청을 받는 서버로).

## 알려진 문제 · 확인 못 한 것
`README.md` 「아직 확인 못 한 것」 외에 1.0.29~1.0.31 에서:
- 자동화 크롬에서는 YouTube 자막이 그려지지 않고, 라이브는 자주 「문제가 발생했습니다」 (음성 번역을 안 켜도) → YouTube 라이브 음성 번역 받아 적기, 자동 CC 라이브 · 일반 영상의 자막 번역은 실제 크롬에서 확인 못 함.
- 윈도우 크롬 157: 음성 인식이 소리는 감지하지만 결과 0건 (맥 안 처리 · 서버 처리 모두). 1.0.31 부터 20초 뒤 「받아 적은 글이 없어요」 안내.
- 맥 음성 번역 실측 (1.0.30, 새 프로필): 영어 5/5 문장 (Route→Root), 일본어 4/4 (仮想→仮装), 실제 ⌥L 키 동작 확인.

## 겪은 실수와 교훈
- 사용자 문의를 처음엔 「윈도우」로 받아 윈도우부터 보다가 「맥이라는데」로 바뀜 → 문의는 **OS · 사이트 · 증상 원문**을 먼저 확인하고 재현한다. 첫 원인(키 · 모델 없음)을 고친 뒤에도 실제 증상(자막 없는 YouTube 에서 안내 없음)은 따로 있었다 — 문의자의 실제 화면 조건으로 재현할 것.
- 안내가 다른 안내에 가려 사용자가 못 봄 (1.0.30) → 사용자가 꼭 해야 할 일 안내는 important 로, 시작 안내에 덮이지 않게.
- `make publish` 는 추적 안 된 `.DS_Store` 가 있으면 멈춘다 → 지우고 다시.
- 커밋 · PR · 머지 · 릴리즈를 한 명령으로 묶으면 자동 승인에서 거부됨 → 단계별로 나눠 실행.
- CDP 로 YouTube 에서 식을 실행할 때 페이지를 지정하지 않으면 YouTube 서비스 워커에 붙는다 → 대상을 page 로.
- YouTube 광고 건너뛰기는 보이는 `button.ytp-skip-ad-button` 을 눌러야 한다.
- 같은 시험 프로필에 확장을 다시 불러오면 서비스 워커가 옛 코드로 남는다 → `Extensions.uninstall` 뒤 다시 불러온다.
